# Agile and Scrum – Hexaware Training Assignments

## Project Overview

This repository contains my practical assignments completed as part of the Hexaware Agile and Scrum training.

The assignments cover Agile principles, Scrum roles, product backlogs, user stories, sprint planning, estimation, daily stand-ups, impediment management, sprint reviews, retrospectives and the Definition of Done.

The work is organised into two main sections: Day 3 – Agile and Scrum, and Day 4 – Doing Scrum.

---

# Day 3 – Agile and Scrum

Day 3 focuses on understanding Agile and Scrum concepts and applying them to different real-world application scenarios.

## Set 1 – Online Grocery Delivery

**Objective:** Develop an Agile product plan for an online grocery delivery application.

Topics covered:
- Product vision and Scrum roles
- Epics and user stories
- INVEST principles and story review
- Acceptance criteria
- Product backlog prioritisation and estimation
- Definition of Ready (DoR) and Definition of Done (DoD)
- JIRA project and backlog setup

**Folder:** `Day-3-Agile-and-Scrum/Set-01-Online-Grocery-Delivery/`

## Set 2 – Insurance Claims Portal

**Objective:** Apply Agile practices to an insurance claims management portal.

Topics covered:
- Product vision and Agile methodology comparison
- Epics and user stories
- INVEST review and story splitting
- Acceptance criteria
- Backlog prioritisation and estimation
- JIRA setup, Definition of Done and Scrum reference

**Folder:** `Day-3-Agile-and-Scrum/Set-02-Insurance-Claims-Portal/`

## Set 3 – Doctor Appointment System

**Objective:** Create an Agile product backlog for a doctor appointment booking system.

Topics covered:
- Product vision and stakeholder identification
- Epics and user stories
- INVEST review
- Acceptance criteria using Given-When-Then
- Backlog prioritisation and estimation
- JIRA setup, Definition of Ready and Definition of Done

**Folder:** `Day-3-Agile-and-Scrum/Set-03-Doctor-Appointment-System/`

# Day 4 – Doing Scrum

Day 4 focuses on practical Scrum execution, including sprint planning, scope changes, daily stand-ups, impediments, sprint reviews and retrospectives.

## Set 1 – Digital Wallet Application

**Objective:** Manage a mid-sprint change request in a digital wallet application.

Topics covered:
- Sprint planning using historical velocity
- Sprint backlog and measurable Sprint Goal
- Breaking user stories into tasks with hour estimates
- Daily stand-up updates
- Backlog reprioritisation
- Sprint burndown tracking
- Sprint retrospective and Definition of Done pipeline mapping

**Folder:** `Day-4-Doing-Scrum/Set-01-Digital-Wallet-Application/`

## Set 2 – Airline Web Check-in

**Objective:** Handle a blocked dependency during an airline web check-in sprint.

Topics covered:
- Sprint capacity calculation
- Sprint planning and Sprint Goal
- Definition of Ready checks
- Impediment logging and escalation
- Backlog refinement and story splitting
- Sprint Review agenda and demo script
- Asynchronous stand-up for distributed teams

**Folder:** `Day-4-Doing-Scrum/Set-02-Airline-Web-Checkin/`

## Set 3 – E-Learning Platform

**Objective:** Handle a scope change during an e-learning platform sprint.

Topics covered:
- Sprint planning using a velocity of 30 story points
- Sprint Goal and sprint backlog
- Certificate-download scope change analysis
- Daily stand-up and impediment management
- Sprint velocity calculation
- Start-Stop-Continue retrospective
- Automation and Definition of Done

**Folder:** `Day-4-Doing-Scrum/Set-03-E-Learning-Platform/`
