## 5. Definition of Ready (DoR)

The Definition of Ready specifies the conditions that a user story should satisfy before the Developers begin working on it.

### DoR Checklist

- [ ] The user story follows the As a / I want / So that format.
- [ ] The business value and purpose are clearly explained.
- [ ] Acceptance criteria are documented.
- [ ] The story is small enough to complete within a Sprint.
- [ ] Dependencies and potential blockers are identified.
- [ ] The story has been estimated by the Scrum Team.
- [ ] Required designs, information, and resources are available.
- [ ] The Product Owner has prioritised the story.

## 6. Definition of Done (DoD)

The Definition of Done describes the quality standards that a product increment must satisfy before it can be considered complete.

### DoD Checklist

- [ ] All agreed functionality has been implemented.
- [ ] The code follows the team's coding standards.
- [ ] Unit tests have been completed successfully.
- [ ] Integration tests have been performed where applicable.
- [ ] Acceptance criteria have been satisfied.
- [ ] Code review has been completed.
- [ ] No critical or high-severity defects remain unresolved.
- [ ] Relevant technical documentation has been updated.
- [ ] The completed functionality has been integrated into the product.
- [ ] The Product Increment meets the agreed quality requirements.

## 7. JIRA Board Implementation

The following activities will be performed in JIRA:

1. Create a Scrum project named Online Grocery Delivery Application.
2. Create the three epics.
3. Add all 12 user stories.
4. Link each story to its corresponding epic.
5. Enter the story descriptions and acceptance criteria.
6. Assign MoSCoW priorities.
7. Add Fibonacci story-point estimates.
8. Configure the workflow statuses.
9. Record the Definition of Ready and Definition of Done.
10. Capture screenshots of the backlog and Scrum board.

## 9. Conclusion

JIRA provides a structured environment for managing the product backlog and monitoring development activities.

The three epics and 12 user stories are organised into a Scrum project. The Definition of Ready ensures that stories are sufficiently prepared before development begins, while the Definition of Done maintains consistent quality standards.

These practices help the Scrum Team collaborate effectively and deliver a potentially usable product increment.
