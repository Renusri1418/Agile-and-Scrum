# Task 1 – Sprint Planning

## 1. Scenario

A fintech team of five developers is working in a 10-day sprint. The previous sprint velocities were 21, 24 and 23 story points. On Day 4, the business requests a refund-to-wallet feature.

## 2. Average Velocity

Average Velocity = (21 + 24 + 23) / 3

= 68 / 3

**Average Velocity = 22.67 ≈ 23 Story Points**

## 3. Sample Product Backlog

The assignment refers to a supplied backlog, but the uploaded assignment document does not include its story table. The following is an illustrative backlog.

| ID | User Story | Story Points |
|---|---|---:|
| US-01 | Register and log in to the wallet | 5 |
| US-02 | View wallet balance | 3 |
| US-03 | Add money to the wallet | 5 |
| US-04 | View transaction history | 3 |
| US-05 | Transfer money to another user | 8 |
| US-06 | Receive transaction notifications | 2 |
| US-07 | Download transaction statement | 5 |
| US-08 | Request a refund to wallet | 5 |

## 4. Selected Sprint Backlog

| ID | User Story | Story Points |
|---|---|---:|
| US-01 | Register and log in to the wallet | 5 |
| US-02 | View wallet balance | 3 |
| US-03 | Add money to the wallet | 5 |
| US-04 | View transaction history | 3 |
| US-06 | Receive transaction notifications | 2 |
| US-07 | Download transaction statement | 5 |
| **Total** | | **23** |

The team selects 23 points, matching its average historical velocity.

## 5. Sprint Goal

**Sprint Goal:** Enable users to securely access their digital wallet, view their balance, add money, review transaction history and receive transaction notifications.

### Measurable Outcomes

- Users can register and log in successfully.
- Users can view their wallet balance.
- Users can add money to their wallet.
- Users can view their transaction history.
- Users receive notifications for wallet transactions.

## 6. Conclusion

The team's average velocity is approximately 23 story points. The team selects a sprint backlog worth 23 points and focuses on delivering essential digital wallet features.
