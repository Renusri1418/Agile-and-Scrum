# Task 5 – Sprint Retrospective

## 1. Introduction

A Sprint Retrospective is an event where the Scrum Team discusses what went well, what problems occurred and how to improve in the next sprint.

The Start-Stop-Continue technique is used to organise the discussion.

## 2. Start

The team should start:

- Sharing API contracts before development begins.
- Identifying external dependencies during sprint planning.
- Conducting regular integration testing.
- Reporting blockers as soon as they occur.

## 3. Stop

The team should stop:

- Delaying the reporting of technical blockers.
- Starting dependent development without required specifications.
- Adding new work without discussing its impact.
- Waiting until the end of the sprint to perform testing.

## 4. Continue

The team should continue:

- Conducting Daily Scrum meetings.
- Collaborating across development and testing.
- Prioritising work based on business value.
- Reviewing progress against the Sprint Goal.

## 5. Three SMART Action Items

SMART stands for Specific, Measurable, Achievable, Relevant and Time-bound.

| Action Item | Owner | Success Measure | Deadline |
|---|---|---|---|
| Document all external API dependencies before development starts | Scrum Master | All dependencies are recorded in the project tracker | Before the next sprint |
| Share API contracts with developers before implementation | Backend Team Lead | All selected stories have approved API specifications | Before the next sprint starts |
| Perform integration testing during development | QA Engineer | All completed integration stories have documented test results | Throughout the next sprint |

## 6. Expected Improvements

- Reduced dependency-related delays.
- Better communication between teams.
- Earlier identification of technical issues.
- Improved testing quality.
- More predictable sprint delivery.

## 7. Conclusion

The retrospective identifies areas where the team can improve its planning, communication and testing. The three SMART action items provide clear responsibilities and measurable outcomes for the next sprint.
