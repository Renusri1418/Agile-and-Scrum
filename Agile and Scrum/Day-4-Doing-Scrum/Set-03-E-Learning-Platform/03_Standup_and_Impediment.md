# Task 3 – Stand-up and Impediment Handling

## 1. Scenario

A developer working on the e-learning platform is blocked because the API contract required for a feature has not been provided.

The missing API contract prevents the developer from completing the integration.

## 2. Developer's Daily Stand-up Update

**Developer:** Backend Integration Developer

### Yesterday
- Reviewed the feature requirements.
- Started preparing the API integration.
- Identified that the API contract was missing.

### Today
- Continue reviewing the technical requirements.
- Prepare the integration code structure.
- Coordinate with the backend team to obtain the API contract.
- Write unit tests using mock responses where possible.

### Impediment
- The required API contract has not been shared.
- The integration cannot be completed without the request and response specifications.

## 3. Impact of the Impediment

- Development work is delayed.
- Integration testing cannot be completed.
- Other dependent tasks may also be affected.
- The sprint delivery may be at risk if the issue remains unresolved.

## 4. Scrum Master's Follow-up Action

The Scrum Master should:

1. Contact the team responsible for providing the API contract.
2. Request the missing API documentation.
3. Identify the person responsible for resolving the dependency.
4. Communicate the impact to the Product Owner.
5. Arrange a discussion between the relevant developers.
6. Track the issue until the contract is available.
7. Help the developer continue independent work while waiting.

| Field | Details |
|---|---|

## 6. Conclusion

The Daily Scrum helps identify impediments early. The Scrum Master works with the relevant teams to remove the blocker and helps the developer continue independent work while the dependency is being resolved.
